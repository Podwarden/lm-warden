An OpenAI-compatible API on the GPUs under your desk or in your rack.

LM Warden runs vLLM v0.32.0 and llama.cpp b11719 on your NVIDIA cards behind one port. Each app gets its own key, and each card reports for itself. Point Claude Code, Codex CLI, OpenCode or another coding agent at it; with Claude Code, a model on your cards can answer for the Claude models you choose, under their names, while the rest go to Anthropic on your own login.

On a Mac: the beta.

A native menu-bar app for Apple silicon that runs models with MLX and shows the same web dashboard in its own window. It is a beta: ad-hoc signed and not notarized, so macOS asks you to confirm before its first launch. Linux with NVIDIA GPUs, above, is still the main way to run LM Warden.

Download for Mac (beta) SHA-256 checksum · release notes on GitHub

About 360 MB. Needs an Apple silicon Mac on macOS 14 or later. Updates are manual: a newer beta is a new download.

  • Menu bar, no Dock icon. It starts and supervises the server, walks you through a first-run setup and can open at login. Open Dashboard shows the web console in a window of its own.
  • MLX first. Models run with MLX. llama.cpp is registered as a second engine, with a Metal build of its server bundled in the app; vLLM is not available on a Mac.
  • This Mac only, until you say otherwise. The server listens on loopback. Share on Local Network opens it to your network, in plain HTTP. For HTTPS, put a reverse proxy such as Caddy, or Tailscale, in front; the app has no TLS of its own.

First launch

  1. Check the download. With the DMG and its checksum file in one folder, run shasum -a 256 -c {{mac_dmg}}.sha256 in Terminal. It prints OK for an intact file.
  2. Open the DMG and drag LM Warden to Applications.
  3. In Applications, double-click LM Warden. macOS refuses it; open System Settings › Privacy & Security and click Open Anyway next to LM Warden. (On macOS 14, right-click LM Warden and choose Open also works.)

Do this only for a download whose checksum matched. The full walk-through is in the install guide.

What it is.

LM Warden is a control plane around two inference engines, vLLM and llama.cpp, that you install on one Linux host with NVIDIA GPUs. You pull a model from HuggingFace, load it onto your cards, give each app its own key, and call it through an OpenAI-compatible /v1 endpoint, through the Anthropic Messages API if the app is Claude Code, or through the OpenAI Responses API if it is Codex CLI. A browser console covers loading and unloading models, live engine logs, a chat playground, GPU and token statistics, and a page per key. It does not make models faster and does not modify the engines. It adds the parts a bare engine does not ship.

There is no hosted service and no account. Every warden serves this page itself, and the Console sign-in link at the top opens that warden’s own console. Nothing leaves your host unless you turn on the Claude Code router described next.

What you get.

  • Coding agents

    Claude Code, Codex CLI, OpenCode, Aider, Cline, Cursor and four more. The console writes each one’s config for you.

  • Agent tuning

    Give Claude Code or Codex an admin token and let it choose the model, the engine and the flags for your cards.

  • GPU monitoring

    One panel per card: temperature against its own throttle point, power against its own cap, and every request in flight.

  • Cache-aware routing

    Each agent session goes back to the replica that already holds its prompt in cache.

  • API keys

    A key per app, with its own priority, usage and queue times. Leaving is a base_url change.

  • Model loads, step by step

    Each load shows its steps with the usual time from earlier loads. A load that stops making progress is stopped and its GPUs freed, not left holding them.

  • More features

    God mode, admin tokens, the engine watchdog, and the lessons behind them.

Don’t use this if…

  • You have no NVIDIA GPU and no Apple silicon Mac. On Linux it runs on NVIDIA cards with CUDA only, and the Mac app is a beta. There is no ROCm, Intel GPU or CPU path yet.
  • You need one model served across several machines. This is one host. Several GPUs in one box, yes; several boxes, no.
  • You want several models resident on one card. One loaded model per GPU is enforced before an engine starts.
  • You need an engine other than vLLM or llama.cpp. TensorRT-LLM, SGLang and Ollama’s runtime are not shipped; MLX runs only in the Mac beta.
  • You want a hosted API. Nobody runs this for you. You supply the hardware, the driver and the electricity.
  • Your host isn’t Linux x86_64 or an Apple silicon Mac. On a Mac you get the beta described above, not the Docker stack.
